## 获取与复现

工作副本只放在 `output/upstream/agency-agents-zh`；产品资源为 `resources/agency-agents-zh`，与src/web一起随桌面包分发，不依赖用户机器的Git或安装上游工具。

1. 获取仓库并 checkout 固定 commit（可禁用Git hooks）。
2. 使用 `./start.sh scripts/import-agency-agents.mjs <repo> <absent-output>`。导入器使用Git ls-tree/cat-file从固定commit读取原始blob，用yaml的安全core schema解析frontmatter。
3. 输出完整profiles、catalog.json/sha256、LICENSE、UPSTREAM、README及ATTRIBUTION。已有目标拒绝覆盖，更新需审阅并选择新目标，避免静默抹掉本地修改。

runtime `ExpertCatalog` 校验索引/许可/全部角色hash、长度和分类计数，破损或缺失时明确失败，不返回假目录或部分正文。包内目录是固定来源；用户自己的助理和指令仍在原SQLite，不被批量替换或污染。

## HTTP / Session / 事件

`GET /api/experts?q=&category=&kind=` →

```js
{
  experts: [{id,name,description,emoji,color,category,categoryName,kind,
    sourcePath,sourceUrl,sha256,characters,bytes}],
  categories: [{id,name,count}],
  total: 278, filteredTotal,
  source: {repository,commit,license,roleCount,primaryRoleCount,
    auxiliaryRoleCount,catalogSha256,...}
}
```

q对名称/描述/分类中文名/源路径做大小写无关的字面多词搜索；category使用真实分类ID（engineering/company/marketing等），kind为expert或integration-example。没有匹配时0结果，不补随机推荐。此接口返回全部匹配元数据，不加载正文到UI列表。

`GET /api/experts/:id`（URL编码ID）返回完整档案+`instructions`原Markdown。没有正文截断。ID格式例如 `agency:engineering:engineering-software-architect`；不存在404，不能把ID变成任意文件路径。

bootstrap新增 `expertCatalog:{source,categories,total}`。Session/create/PATCH新增 `expertId:''`，空串保持通用助手；非空必须来自当前真实目录，运行中不能改角色。expertId单独持久化，不向用户assistants表插入278行。原用户assistantId、skills、标题/历史/配置均保留，已有会话迁移默认expertId为空。

Run启动时捕获完整专家定义，system注入专业方法/风格与来源，明确原角色中履历、工具或服务声明不等于宿主真实能力或授权。宿主仍执行模式/只读/审批/凭证/取消规则；角色不能升级权限。`expert_loaded` SSE/event含 `{expertId,name,category,sourcePath,sha256,characters,bytes,sourceCommit,truncated:false}`，便于核实本轮实际使用哪份角色。

## 模型发现与协作

只读工具：

- `list_experts({q?,category?,kind?,limit?:1..30,offset?:0..})`：默认20位，返回真实元数据+filteredTotal/hasMore/nextOffset；可取全部目录，不用通用工具输出截断来冒充全量发现。
- `load_expert({id})`：完整角色正文和出处。此工具响应不受普通工具16000字符摘要上限截断，超出实际本地上下文预算时明确失败；不是偷偷截断。
- `delegate_task({prompt,title?,mode?:'ASK'|'AGENT',expertId?})`：真实独立session/run。显式ID选择专家；省略继承父角色，空串选择通用助手。无效专家在创建子会话前报错。

单次父运行最多12个delegate_task，单层、不递归。同批全部是delegate_task时按最多3项并发分批调度，五成员按3+2实际启动，多轮串行也可以超过3项。父只读时子不能升级AGENT；子写入照常审批。拒绝/父取消终止正在执行的其他成员，后续批次不启动；该批所有declared tool结果按原序持久化，未启动成员明确返回NOT_EXECUTED而不造输出。子会话、subtask_started/subtask_done、tool result与GETsubtasks都带expertId/expertName（GETsubtasks最少带expertId，可从目录查名称）。父模型真正收到各子任务的status/output/artifacts再综合。

这提供真实专家协作，但不是安装上游独立agency-orchestrator，也不声称完整DAG/无限团队/上游云服务已连接。任何角色里的脚本代码只是角色文本，不自动执行。
